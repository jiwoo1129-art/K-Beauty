# COMPLY.AI 다중 페이지 Listing Studio 설계

## 목표

현재 화이트·주황 디자인과 제품·스캐닝 모션을 유지하면서, 참고 사이트의 Listing 작성·검증 흐름을 같은 사이트의 별도 페이지로 제공한다.

## 화면 구조

- `/`: 현재 랜딩 화면. 주요 버튼은 각각 `/write`, `/validate`로 같은 창에서 이동한다.
- `/write`: 제품 정보를 입력하고 Amazon US Beauty 상세페이지를 생성·편집한다.
- `/validate`: 기존 TXT/HTML 상세페이지를 불러와 문장별 정책 위험과 수정안을 확인한다.
- 모든 화면에 공통 헤더, 홈 링크, 작성·검증 메뉴, 테마 전환을 제공한다.

## 기능

### Listing 작성

- 브랜드명, 제품명, 제품 유형, 용량, 원산지 등 필수 정보 입력
- 성분, 특징, 제형·사용감, 고객, 사용법, 주의 사항, 브랜드 톤, 키워드, 효능 근거 입력
- 선택형 입력과 직접 입력을 함께 지원
- 텍스트 선택이 가능한 PDF에서 제품 정보를 브라우저 내부에서 추출해 입력 보조
- Title, Bullet Points, Description, Search Terms 생성 및 항목별 편집
- 전체 복사, TXT 다운로드, 생성 결과 정책 검토

### Listing 검증

- TXT/HTML 파일 또는 붙여넣기 입력
- 문장별 위험도, 위치, 이유, 정책 근거, 수정안 표시
- 수정안 적용·제외 및 수정된 문구를 `/write`로 전달

### 기존 기능 유지

- 브라우저 로컬 자동 저장
- 작업 생성·복제·삭제, 버전 저장·복원, JSON 백업·가져오기
- 라이트·다크 테마, 반응형 UI, 키보드 접근성, 모션 감소 설정

## 구현 구조

- 별도 라우터 의존성 없이 `window.location.pathname`과 History API로 세 화면을 전환한다.
- 기존 `StudioWorkspace`, 생성기, 검증 엔진, 저장소를 재사용하고 작성·검증 페이지에서 필요한 입력과 동작만 확장한다.
- 페이지 간 전달 데이터는 기존 로컬 작업 저장소에 기록해 새로고침 후에도 유지한다.
- PDF 텍스트 추출은 브라우저용 PDF 파서 한 개만 사용하며, 원본 파일은 업로드하지 않는다.

## 오류 처리

- 지원하지 않는 파일 형식·크기·텍스트 추출 실패를 입력 영역에서 안내한다.
- 필수 제품 정보 누락 시 첫 누락 필드로 초점을 이동한다.
- 생성·검증 결과가 없을 때 다음 행동을 설명하는 빈 상태를 표시한다.
- 자동 결과가 정책 준수를 보증하지 않는다는 안내를 유지한다.

## 검증 기준

- 홈 버튼이 같은 창에서 `/write`, `/validate`로 이동한다.
- 참고 사이트의 작성 필드, 생성 결과, 복사·다운로드, 파일 검증 흐름이 동작한다.
- 페이지 이동과 새로고침 후 작업 데이터가 유지된다.
- 기존 화이트·주황 스타일, 제품·스캐닝 모션, 테마 전환이 유지된다.
- 데스크톱·모바일에서 핵심 흐름과 키보드 조작이 가능하다.
