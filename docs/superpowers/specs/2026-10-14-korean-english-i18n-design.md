# COMPLY.AI Beauty Listing Studio 한·영 국제화 설계

## 목표

기존 UI/UX, 레이아웃, 스타일, 색상, 폰트, 애니메이션, 페이지 구조와 모든 작업 기능을 유지하면서 한국어와 영어 UI를 제공한다. 기본 언어는 한국어이며 사용자가 선택한 언어는 브라우저에 저장한다.

Amazon US용 Listing 산출물 자체는 영어로 유지한다. 언어 전환 대상은 내비게이션, 버튼, 입력 라벨과 도움말, 플레이스홀더, 상태·오류 메시지, 검증 결과 설명 등 사용자 인터페이스다.

## 접근 방식

### 채택: 전역 언어 Context와 중앙 번역 사전

- 외부 패키지를 추가하지 않고 React Context로 현재 언어와 번역 함수를 제공한다.
- 번역 키와 한국어·영어 문구는 한 모듈에 모아 누락을 검사하기 쉽게 한다.
- `App`에서 `localStorage`의 언어를 읽고, 값이 없거나 잘못됐으면 한국어를 사용한다.
- 언어 변경은 번역 문자열만 다시 렌더링하며 기존 컴포넌트 상태와 작업 저장소는 유지한다.
- 현재 헤더 오른쪽에 기존 스타일을 재사용한 한국어/English 토글을 추가한다.

### 검토했지만 채택하지 않은 방식

- 컴포넌트별 조건문: 파일 수는 적게 늘지만 문구가 흩어지고 누락 검증이 어렵다.
- 외부 i18n 라이브러리: 기능은 풍부하지만 두 언어의 정적 UI에는 의존성과 변경 범위가 불필요하게 커진다.

## 컴포넌트와 데이터 흐름

1. `LanguageProvider`가 초기 언어를 `localStorage`에서 읽는다.
2. 토글이 언어 상태를 바꾸고 즉시 `localStorage` 및 문서 `lang` 속성에 반영한다.
3. 화면 컴포넌트는 번역 키를 통해 현재 언어의 문자열을 렌더링한다.
4. Listing 작성 폼, 업로드 파일, 생성 결과, 검증 결과, 작업 저장소는 언어 상태와 분리한다.
5. 정책 규칙의 결과 객체는 언어 독립 식별자를 유지하고, 표시 단계에서 이유·수정 안내를 번역한다.

## UI 보존 원칙

- 기존 DOM 계층과 CSS 클래스는 가능한 한 유지한다.
- 토글 외에는 새 시각 요소를 추가하지 않는다.
- 토글은 현재 top-right navigation 안에서 기존 버튼 높이·간격·테두리·타이포그래피 규칙을 따른다.
- 한국어와 영어 문구 길이 차이가 있어도 반응형 구조와 기존 브레이크포인트를 유지한다.

## 오류 처리

- 저장된 언어 값이 `ko` 또는 `en`이 아니면 한국어로 복구한다.
- 번역 키가 없으면 개발 중 테스트가 실패하도록 두 언어 사전의 키 집합을 비교한다.
- 브라우저 저장소 접근 실패 시에도 현재 세션에서는 한국어로 정상 동작한다.

## 테스트 및 검증

- 번역 사전의 한국어·영어 키가 완전히 일치하는지 자동 검사한다.
- 기본 언어가 한국어인지, 저장된 영어가 복원되는지, 잘못된 값이 한국어로 복구되는지 검사한다.
- 언어 전환 후 입력값과 작업 상태가 유지되는지 브라우저 테스트로 확인한다.
- 모든 주요 화면(`/`, `/write`, `/validate`)에서 한국어와 영어 문구가 표시되는지 확인한다.
- 기존 전체 테스트와 프로덕션 빌드를 실행한다.
- 데스크톱·모바일 화면을 비교해 토글 외 레이아웃과 스타일이 유지되는지 확인한다.

## 배포

Vite 설정이 상대 경로 기반 정적 빌드(`base: './'`)를 지원하므로 GitHub Pages에 배포할 수 있다. 저장소의 실제 기본 브랜치와 Pages 설정을 확인한 뒤 GitHub Actions로 `dist`를 배포하고, 직접 URL 진입 시 라우팅이 유지되도록 정적 호스팅 동작을 검증한다.
